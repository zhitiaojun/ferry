# ft 界面设计任务书（M10 输入）

> 给设计协作者：读完本文即可产出界面方案，不需要读代码。要求见 §6「交付物」。

## 1. 产品是什么

ft 是一个**文件传递工具**，同一账号下的自有设备之间互传文件，自动选路：

1. 同一局域网 → 直连（最快，标注 `LAN`）
2. 跨网络但 NAT 可打洞 → UDP 打洞直连（标注 `打洞`）
3. 打洞失败 → 服务器中继（最稳，标注 `中继`）

用户操作只有两件事：**把文件拖/选进来发给某台设备**，或**开着接收等别人发**。没有账号、没有云盘、没有文件夹同步，不做聊天。

已上线形态：
- Windows 桌面端：常驻托盘 + 主窗口（本次重做重点）
- Android App：接收/发送、扫码或 6 位码配对、网页分享
- 浏览器端：`https://ft.cwlindean.cn/`（伪装页 → 口令 → 选设备传文件），非本次重做重点

## 2. 技术架构（决定界面能做什么、不能做什么）

```
Windows 桌面端                         Android App
┌──────────────────────────┐          ┌──────────────────────────┐
│ cmd/ft-desktop           │          │ MainActivity.java (UI)   │
│   纯 Win32 + GDI 自绘     │          │   ↕ gomobile 绑定        │
│   （无 WebView/无 cgo）   │          │ core/mobile (Go)         │
└──────────┬───────────────┘          └──────────┬───────────────┘
           │                                     │
           └──────────► core/  ◄────────────────┘
                 identity / signaling / punch / relay /
                 transfer / pathmgr / client / discovery
```

- 桌面端**不能**用 WebView：常驻内存预算 8–15 MB，浏览器引擎 120–250 MB，已被否决。所有界面用 GDI 画（矩形、文字、线条、位图），字体用系统字体（`Microsoft YaHei UI`、`Consolas`）。
- Android 端是原生 Java View + gomobile 导出的 Go 函数；没有 Compose，也没有 Gradle 依赖注入，动画以属性动画/Canvas 为主。
- 两端的业务逻辑都在 Go 里，界面只读状态、发起命令。

## 3. 界面可用的数据（真实字段）

**本机**
- 设备名（可改，默认主机名，如 `HyperX` / `android-M332BF`）
- 设备 ID：64 位十六进制，界面只显示前 12 位（如 `91695a021bdb`）
- 接收端口（如 `18820`）、接收中 / 已暂停
- 版本（`0.8.0`）

**已配对设备**（`ft pair` 建立，长期有效）
- 名称、设备 ID（前缀显示）、最近一次传输时间

**一次传输记录**
- 方向：收 / 发
- 对端：名称 + ID 前缀
- 文件：文件名列表（可能多个）
- 字节数：如 `2,100,000` → 显示 `2.1 MB`
- 分块数、耗时（ms）
- 路径：`lan` | `punch` | `relay`
- 结果：成功 / 失败（失败带中文原因，如「对端未配对」「网络超时」）

**实时状态**
- 当前传输：文件名、已传/总量、百分比、速率（可选，不测速所以只做进度）
- 接收开关：开 / 关（关掉后仍监听端口但拒新会话）

## 4. 两端各自的约束

| | Windows 桌面 | Android |
|---|---|---|
| 尺寸 | 主窗口默认 880×468，可缩放（最小 720×420） | 390×844 @3x |
| 输入 | 拖放、单击选中、右键菜单（已有一级菜单项） | 触摸、系统文件选择器、分享菜单 |
| 常驻 | 托盘图标 + 通知气泡 | 前台服务通知 |
| 主题 | 跟随系统浅色/深色 | 跟随系统浅色/深色（Material You 动态色可选） |
| 文案 | 简体中文，数字用等宽 | 同 |

## 5. 设计要求

1. **信息密度优先**：这是一台设备的“操作面板”，不是营销页。一屏内要能同时看到「设备」「投放区」「最近传输」「接收开关」。
2. **路径可读**：`LAN` / `打洞` / `中继` 必须有稳定的视觉编码（文字标签 + 颜色/形状），用户要能一眼判断这次是直连还是走服务器。
3. **数字要对齐**：文件大小、耗时、时间用 tabular 数字，右对齐。
4. **安静**：几乎没有装饰性动画；只有“正在接收”有一个克制的呼吸/进度指示。
5. **两种极端状态都要好看**：空状态（还没有配对设备）与繁忙状态（多设备 + 正在传 2.1 MB）。
6. 不做：暗色霓虹赛博、玻璃拟态、大面积渐变、圆角卡片堆砌、营销式大标题。

## 6. 交付物（每个方案一份）

```
design/variants/<方案名>/
  index.html    # 单文件，内联 CSS/JS，无外链资源、无 CDN、无 web font
  notes.md      # 设计取向、色板/字体/间距 token、与默认方案的差异
```

`index.html` 里并排放两个画框（同一份样式，两套密度）：

- **桌面画框**：内容区 1060×680，模拟窗口（含标题栏「ft · 文件传递」），展示：
  - 左栏：3 台已配对设备（`HyperX` 本机选中、`android-M332BF`、`MacBook Pro`），带设备 ID 前缀与最近传输时间
  - 右栏：投放区（虚线框 + “拖文件到这里，或选择文件”）、传输按钮「发送到 android-M332BF」
  - 底部/右侧：最近传输台账 4 条，分别覆盖 `LAN 12 ms`、`打洞 2.1 s`、`中继 3.1 s`、一次失败
  - 顶部：本机名 · 设备 ID · 端口 · 「接收中」开关
- **手机画框**：390×844，展示同一台设备的移动端：设备列表 + 一个大「接收」开关 + 最近传输 3 条 + 底部「扫码配对」入口。

交互不必真跑，但 HTML 必须能在 Chrome 里静态打开就呈现完整视觉（可用少量 JS 切换「接收中/已暂停」「有设备/空状态」两个状态，做成页面内的切换按钮更好）。

## 7. 现有视觉基调（可继承也可推翻，但请说明理由）

当前主窗口是「系统色 + 台账」风：左栏设备列表、右侧投放区、最近传输表格、底栏按钮；强调色偏墨绿，路径标签用文字。设计稿可以完全另起一套，只要满足 §5。
