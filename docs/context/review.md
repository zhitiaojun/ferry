## 1. 传输层：统一“会话层 + 可替换路径”

**问题**：设计中 LAN 用 TCP、打洞用 UDP、中继协议未定，三条路的可靠性语义不同；切流“重放未确认分块”需要每条路都有同一套确认机制。

**建议架构**（四层，自下而上）：

```
路径层 path transport   LAN: TCP  | 打洞: QUIC over UDP | 中继: TCP / WebSocket（经 BJ 拼接）
  ↓ 都抽象成“可靠有序字节流”
会话层 session           session_id、偏移量确认（cumulative ack）、切路径、去重
  ↓
传输层 transfer          文件清单、64 KiB 分块、每块 SHA-256、整文件 SHA-256、进度
  ↓
选路层 pathmgr           三路竞速、0.5 s 窗口、升级/降级（只做决策，不碰 socket）
```

要点：

- **UDP 路径不自研可靠传输**（A1）。QUIC 自带重传、拥塞控制、多流和 TLS 1.3；打洞时让 STUN 探测与 QUIC 共用同一个 UDP socket（端口映射才一致）。备选 KCP（无加密、实现简单）。
- **中继只做 TCP/WebSocket 字节流拼接**，不做 UDP 中继：UDP 中继上面还得再套可靠层，而 TCP 拼接可直接复用内核可靠性，内存可控（每会话两个 64 KiB 缓冲），浏览器也能用。前提是 BJ 的 TCP 端口放行（`NOW.md` 阻塞 1 因此升级为关键阻塞）。
- **切路径按偏移量**：接收端按 offset 写文件并回传“已连续收到的最大偏移”；切路径时发送端从该偏移继续。这与 D5（不做断点续传）不冲突——它是同一会话内的续传，进程退出即作废。

## 2. 会话与配对模型（A3）

```
1. 发送端 → BJ 信令：CREATE      ← 返回 session_id、6 位会话码、relay_token
2. 接收端 → BJ 信令：JOIN(会话码) ← 返回同一 session_id、relay_token
3. 双方经信令交换候选：LAN 地址、IPv4 外网映射（STUN 观测）、IPv6 地址、NAT 类型
4. 局域网广播内容带 hash(session_id)，只有同会话的对端响应
5. 三路竞速开始（§3）
```

- 无服务器的纯局域网模式：广播“设备名 + 一次性短码”，用户在接收端确认（对应最终 UI 的“附近设备”）。
- 会话码在阶段 5 升级为 PAKE（参考 magic-wormhole 的 SPAKE2），同时解决鉴权和端到端密钥。

## 3. 竞速状态机细化（对 design.md §2 的修正）

```
t=0     并发：LAN 发现 | 信令 + STUN | 中继建连（只握手，不发数据）
t≤0.5s  LAN 通 → 用 LAN，取消其他（中继零流量）
t=0.5s  LAN 未通 → 中继开始承载数据（D3）
任意时刻 打洞/IPv6 直连成功 → 在新路径上 HELLO 确认 → 按偏移量切流 → 关闭中继数据流
任意路径 3 s 无进展 → 降级到下一条可用路径
```

- 升级判据要“可写 + 对端确认 + 实测吞吐不低于当前路径”，避免切到一条更慢的直连（部分蜂窝 UDP 被限速）。
- 每次选路/切换都写结构化日志：`{ts, session, event:"path_switch", from:"relay", to:"punch", offset}`。

## 4. 技术栈路线（A2，需用户选）

| 路线 | 组成 | 优点 | 缺点 |
|---|---|---|---|
| **A（推荐）Go 单核心** | 一份 Go 核心：Windows CLI（单 exe）、BJ 服务端、安卓经 gomobile 编成 AAR，外壳仍是 Java/Kotlin 原生 APK | 协议只写一次；quic-go 支持同 socket 收发非 QUIC 包（打洞友好）；服务端常驻内存约几十 MB，远低于 256 MB；交叉编译简单 | 安卓包体增加若干 MB；需确认“APK 内含 Go 原生库”符合 D6 的本意 |
| B 维持现状 | 桌面 Node 24 + 安卓 Java + 服务端 Node | 不改既有设想 | 协议写两遍；Node 的 QUIC 仍属实验特性，UDP 可靠层得自己写或找库；Node 服务端内存余量较小 |
| C Rust + iroh | iroh 已实现“中继先载、打通后升级”，含局域网发现 | 最省 L2/L3 工作量 | 采用 iroh 自有协议与中继，可控性和“验证自研可行性”的目的打折；Rust/JNI 学习成本；具体能力以当时版本核实 |

无论选哪条，都先写 `docs/spec/protocol.md`（帧格式、状态机、错误码）+ 二进制测试向量，所有端以此做一致性测试。

## 6. 新增风险建议（待写入 `RISKS.md`）

- **R9 中继被滥用**：公网端口无鉴权 → 流量费与带宽被占。保护：会话令牌 + 每会话限速 + 会话总数上限 + 空闲超时。
- **R10 安卓后台限制**：Android 14+ 前台服务须声明类型，`dataSync` 类型在新版本有时长限制；组播需 `MulticastLock`。保护：M2 内实测，传输期间前台服务 + 通知。
- **R11 运营商 UDP QoS**：部分蜂窝网络对 UDP 限速或丢弃，打洞成功但吞吐低于中继。保护：升级判据含吞吐对比（§3）。
- **R12 双实现漂移**（若选路线 B）：保护：协议规范 + 测试向量 + 互通测试进 CI。
