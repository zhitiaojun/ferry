# 需求与验收（requirements）

> 本文件是需求与验收判据的**唯一权威来源**。标「待确认」者为我方草拟、用户尚未表态，不得当作已生效标准。
> 更新：2026-11-07（第四轮：D28 VPN / TUN 场景）。

## 1. 目标

**以自有固定设备（我的安卓手机 ↔ 我的 Windows 电脑）之间的最佳传输体验为主，兼顾给陌生设备传文件**（D12）。链路按可用性降级：

| 档位 | 触发条件 | 路径 | 期望特征 |
|---|---|---|---|
| L1 局域网 | 同一网段可互通（学校网络有概率、手机热点必然） | 设备 ↔ 设备直连 | 最快，不经服务器 |
| L2 打洞 | 不同网络，NAT / 防火墙允许 | IPv6 直连或 IPv4 打洞 | 接近直连 |
| L3 中继 | 直连失败 | BJ 经 443 转发 | 总能通，受 BJ 带宽限制 |

三档**并发尝试**（D2）；局域网候选 0.5 s 未通即由中继先承载（D3），直连打通后热切换。

## 2. 功能范围

### v1.0 必须（D19、D20）

自有设备：

- 一次配对（扫码或输码），之后打开即自动连接，无需再输码。
- 电脑托盘常驻、手机后台接收：对方不打开 App 也能收。
- 手机系统分享菜单、电脑右键菜单一键发送。
- 电脑上拖动文件时，右下角弹出投放小窗，拖进去即发送到已配对设备。
- 断点续传：断网或切网后接着传。
- 单文件与多文件，保留文件名与大小；进度与失败提示。

陌生设备：

- 对方不装 App：浏览器打开链接或扫二维码收发（仅局域网 + 中继，D7）。
- 同一局域网显示附近设备，点选后对方确认。
- 对方装了 App：输入一次性会话码。

通用：全链路加密；分块 + SHA-256 校验。

- **VPN（TUN）兼容（D28）**：任一端或双方开启 TUN 模式 VPN 时可正常传输，不挂起、不静默失败；客户端检测 VPN 状态写入日志与诊断信息；能绕过 VPN 直连就直连，否则经 VPN 走中继；必要时提示用户把本应用 / `ft.cwlindean.cn` / `123.57.253.208` 加入 VPN 的直连规则。

### 不做（v1.0）

iOS、账号体系、文件夹递归、剪贴板同步（未选，暂不做）、离线留存（对方不在线时由服务器暂存）。

### 骨架阶段（M1–M4）的简化

无图形界面、命令行驱动；可明文（D4）；不做续传（D5）。

## 3. 验收判据

| 里程碑 | 判据 |
|---|---|
| M1 本机 | 本机双进程互传 2.1 MB 与 10 MB，SHA-256 一致，进程内存不随文件大小线性增长 |
| M2 局域网 | **手机热点场景**（电脑连手机热点）双向传输必通，SHA-256 一致；**学校网络**下记录发现 / 直连成功与失败的次数和原因（不要求必通） |
| M3 中继 | Win（Wi-Fi）↔ 安卓（电信蜂窝）经 BJ 443 中继完成 2.1 MB 与 10 MB 传输，SHA-256 一致；BJ 内存 < 256 MB |
| M4 打洞 | 每次跨网传输记录 NAT 类型、候选与最终档位；直连成功则日志显示从中继切走且中继字节数停止增长；失败则可观测地回退中继并完成传输（D26） |
| M5 浏览器 | 浏览器同 Wi-Fi（L1）与外网（L3）双向收发，SHA-256 一致 |
| M6 安全 | 三条路径抓包无明文；伪造身份 / 错误配对码无法连接 |
| M7 产品 | 见 `PLAN.md` G7（自有设备体验逐项验收） |

**性能（D23）**：不测速、不设门槛。验收只看三点：链路技术上走通、实际档位符合预期（有日志与对照证据）、SHA-256 一致。吞吐与耗时作为日志字段记录，仅用于诊断。BJ 带宽 200 Mbps 共享（D27），晚高峰中继变慢属预期，不算缺陷。

## 4. 测试矩阵

| 编号 | 发送端 | 接收端 | 期望档位 |
|---|---|---|---|
| T1 | Win 学校网络 | 安卓 同一学校网络（部分隔离） | L1（有概率）→ 否则 L2 / L3，记录结果分布 |
| T1b | Win 连安卓手机热点 | 安卓（热点主机） | **L1 必通**；不得走中继（否则手机流量被双倍消耗） |
| T1c | Win 学校网络 | 安卓 电信蜂窝 | L2 / L3 |
| T2 | Win Wi-Fi | 安卓 电信蜂窝 | L2（失败则 L3） |
| T3 | Win Wi-Fi | 浏览器 同网 | L1 |
| T4 | Win Wi-Fi | 浏览器 外网 | L3 |
| T5 | 安卓 电信蜂窝 | Win Wi-Fi（T2 反向） | L2 / L3 |
| T6 | 同 T2，禁用打洞 | | L3（对照） |
| T7 | 同 T2，禁用中继 | | 直连或明确报错（不得挂起） |
| T8 | 同 T2，双方有 IPv6 | | L2 IPv6 |
| T9 | 传输中切网（Wi-Fi ↔ 蜂窝） | | 自动续传（M7） |
| T10 | Win 开 VPN（TUN）| 安卓 同网 / 热点 | L1（局域网流量应绕过 TUN）；失败需有诊断原因 |
| T11 | Win 开 VPN（TUN）| 安卓 电信蜂窝 | 直连（绑定物理网卡）或 L3；不得挂起 |
| T12 | 安卓开 VPN（TUN）| Win 任意网络 | 同上；记录 VPN 是否允许本应用绕过 |
| T13 | 双方都开 VPN（TUN） | | L3 必通；记录实际出口（是否经 VPN 节点） |

VPN 用例的记录要求：每次记录两端 VPN 开关、TUN 网卡名、是否 fake-ip（`ft.cwlindean.cn` 解析结果是否为 198.18.0.0/15 段）、STUN 观测到的公网地址是否为 VPN 出口。

对照组（排除静默回退）：每个“L1/L2 成功”的用例，需同时给出中继字节数为 0（或切换后不再增长）的服务器日志。

## 5. 约束

- 服务器仅 BJ（D8）；内存上限 256 MB（D9）；允许常驻服务（D15）。
- 443 经新子域名使用，只 `nginx -t` + reload（D16）；UDP 40000 段用于 STUN / 打洞（D17）。
- 测试文件 2.1 MB 与 10 MB；蜂窝流量适度（D10、D11）。

## 6. 待核实

- 学校网络是否下发全局 IPv6（教育网普遍有，M4 实测；若有，IPv6 直连可能是学校场景的主力直连路径）。
- 学校网络对出站 UDP 的限制（影响打洞与 STUN）。
- 用户实际使用的 VPN 客户端与配置（D28 未决项）。
