## 2. 网络与防线

- 本机**无入站过滤**：`nft list ruleset | grep -c 'hook input'` = 0；1Panel 的 `1PANEL_BASIC_*` 链未挂 hook，不生效。
- 公网暴露面靠**绑定地址**收敛：只有 openresty（80/443）与 sshd（22）绑 `0.0.0.0`；其余服务绑 `127.0.0.1` 或 `172.19.0.1`。
- 外层防线是**阿里云安全组**（本机不可见）。已开：22、80、443；用户确认 **UDP 40000-40100 已开**（TCP 未开，按 D17 不需要）。
- 新服务的约定（沿用既有做法）：业务进程只绑 `127.0.0.1:<端口>`，openresty（host 网络）反代；需对公网收 UDP 的进程才绑 `0.0.0.0:<UDP 端口>`。

## 3. 站点与证书（openresty + 1Panel + ESA）

- 现有站点均在 `cwlindean.cn` 下（api / wash-api / status / cloud / temp / bat），全部经**阿里云 ESA 代理**（解析到 ESA 边缘地址，回源 BJ）。
- 站点配置：宿主 `/opt/1panel/www/conf.d/<域名>.conf`，反代片段放 `/opt/1panel/www/sites/<域名>/proxy/*.conf`（被站点 conf `include`）。
- 证书：1Panel 申请，DNS-01（AliESA），自动续期；**站点不存在时证书不会落盘**，需导出到 `sites/<域名>/ssl/`（`battery-alert` 已踩过此坑）。BJ → Let's Encrypt 链路抖动，申请超时可直接重试（注意每周 5 张限速）。
- 可复用模板：`battery-alert`（2026-11-03）= 回环端口 + 独立子域名站点 + `proxy/*.conf` + 一键脚本（校验证书 → 建站点 → 写反代 → `nginx -t` → reload → 自测）。本项目部署照此执行。
- 改动规则：只允许 `nginx -t` + reload；**禁止 restart openresty**（全站断流）。

## 5. 资源配额与边界

- 本项目内存上限 **256 MB**（D9），用 systemd `MemoryMax=256M` 强制；Go 运行时另设 `GOMEMLIMIT`。
- 允许常驻一个 systemd 服务（D15）。
- 80/443 只通过新增子域名站点使用；改 openresty 前告知具体变更（D16、`AGENTS.md` §4）。
- 改动 BJ 后回写运维仓库 `修改log.md` 与《服务器信息-BJ》。
- 禁止部署到 LA-DR 与 rn。
- 不在 BJ 上开无上限抓包（2026-11-01 曾有 tcpdump 写满 13 G 的事故）；排障抓包必须带 `-C/-W` 与时限。
