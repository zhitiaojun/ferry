# 界面方案 A「仪表台账」说明

文件：`mock-desktop.html`（单文件，自包含，双击可开；右上角可切深色）。
对应任务书 `dist/ui-brief/ft-ui-brief/README.md`。

## 一句话

把 ft 做成一台**仪器**：纸面/墨色、宋体标题、等宽数字、发丝分隔线；三条路径用**印章**表示（颜色 + 边框 + 文字三重编码）；全程只有“传输中”的呼吸点在动。

## 为什么是这套

1. 两个界面尺寸差很大（主界面 880×520，面板 360×260），共享同一套排版骨架（标题 / 台账 / 印章）比共享组件更省事。
2. 台账是这个产品的核心资产：用户真正关心“刚才那次走的哪条路、多快、为什么失败”。表格 + 等宽数字比卡片墙更好扫。
3. 路径不能只靠颜色：`LAN / 打洞 / 中继` 同时用印章边框、字间距、颜色区分，深色模式和色弱都可读。
4. 面板要极小且不抢焦点：只有“目标设备 + 松手”两件事，设备芯片可点选/键盘切换。

## 令牌

| 名称 | 浅色 | 深色 | 用途 |
|---|---|---|---|
| 纸 | `oklch(0.972 0.008 95)` | `oklch(0.185 0.012 165)` | 窗口底 |
| 纸 2 | `oklch(0.949 0.010 95)` | `oklch(0.225 0.014 165)` | 投放区/悬停 |
| 墨 | `oklch(0.235 0.018 165)` | `oklch(0.925 0.010 95)` | 正文 |
| 林绿 | `oklch(0.435 0.062 165)` | `oklch(0.780 0.075 165)` | 主操作/LAN/接收中 |
| 失败 | `oklch(0.535 0.155 28)` | `oklch(0.720 0.135 28)` | 失败/未配对 |

字体：标题 `Iowan Old Style / Songti SC`；正文 `Segoe UI / Microsoft YaHei UI`；数字与标签 `Cascadia Mono / Consolas`。
行高密度：台账行 8px 上下内边距，设备行 34px 固定高度。

## 落到 GDI（Win32 自绘）的取舍

| 稿里的效果 | GDI 实现 |
|---|---|
| 圆角 6–11px | `RoundRect` + 同底色调 `CreatePen` |
| 一层柔和投影 | 不画真阴影，用 1px 浅色描边 + 窗口外偏 2px 的 `SetLayeredWindowAttributes` 仅做位置阴影 |
| 半透明拖拽 ghost | 不实现；面板本身不透明 |
| 呼吸点 | `SetTimer` 40ms 逐帧画半径 3–7px 的圆 |
| 宋体标题 | `CreateFontW("Songti SC"/"SimSun")`，回退 `Microsoft YaHei UI` |
| 印章边框 | `Rectangle` 1px + `DrawTextW` 小号等宽 |

## 已知没做的

- 空状态（无设备/无记录）只给了文字位，未单独做图。
- 传输失败的重试入口只在台账里有色标，没做展开菜单。
- 手机端未做深色稿（令牌已给，可直接推）。
